# Telegram Anti-Spam Bot Factory

یک «ربات ساز» تلگرام: با یک **ربات مدیر** (Manager Bot) کاربران می‌توانند ربات ضداسپم
اختصاصی برای گروه خود بسازند. هر ربات ضداسپم از **CAPTCHA تصویری** برای جلوگیری از ورود
اسپمرها استفاده می‌کند و فقط در یک گروه کار می‌کند.

[![Python](https://img.shields.io/badge/Python-3.10%2B-blue.svg)](https://www.python.org/) [![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](https://opensource.org/licenses/MIT)

## معماری
پروژه به‌صورت ماژولار بازنویسی شده و لایه‌ی داده روی **PostgreSQL + Redis** است:

| فایل | نقش |
|------|-----|
| `antispambot.py` | نقطه‌ی ورود ربات مدیر (ساخت/حذف/مانیتور ربات‌ها) |
| `child_bot.py` | ربات ضداسپم **ثابت**؛ کانفیگ را از env می‌گیرد و توسط مدیر اجرا می‌شود |
| `captcha.py` | تولید تصویر CAPTCHA (مشترک) |
| `db.py` | لایه‌ی داده: connection pool امنِ Postgres + کلاینت Redis |
| `process_manager.py` | اجرا/مانیتور/توقف امن پروسه‌های فرزند |
| `config.py` | خواندن env و راه‌اندازی logging |
| `docker-compose.yml` | سرویس‌های Postgres و Redis برای توسعه |

- **PostgreSQL** داده‌ی ماندگار را نگه می‌دارد: ربات‌های ثبت‌شده، تلاش‌های ناموفق، کاربران
  تاییدشده و گروه مجاز هر ربات. دسترسی از طریق connection pool چند-thread امن است.
- **Redis** داده‌ی موقت را با TTL نگه می‌دارد: چالش‌های CAPTCHA در انتظار و وضعیت گفتگوی
  مدیر. انقضای خودکار جای thread پاک‌سازی قدیمی را گرفته است.
- ربات فرزند دیگر به‌صورت رشته تولید نمی‌شود؛ یک اسکریپت ثابت است و توکن آن **فقط** از راه
  متغیر محیطی به پروسه داده می‌شود (نه نوشتن در فایل).

## پیش‌نیازها
- Python 3.10 یا بالاتر
- PostgreSQL و Redis (یا Docker برای اجرای محلی آن‌ها)
- کتابخانه‌ها: `pip install -r requirements.txt`

## راه‌اندازی

۱. سرویس‌های داده را بالا بیاورید (با Docker):
```bash
docker compose up -d
```

۲. کتابخانه‌ها را نصب کنید:
```bash
pip install -r requirements.txt
```

۳. متغیرهای محیطی را تنظیم کنید:
```bash
export MAIN_BOT_TOKEN='توکن-ربات-مدیر-از-BotFather'
export DATABASE_URL='postgresql://antispam:antispam@localhost:5432/antispam'
export REDIS_URL='redis://localhost:6379/0'
```
> با استفاده از `docker-compose.yml` این مقادیر `DATABASE_URL`/`REDIS_URL` به‌صورت
> پیش‌فرض کار می‌کنند.

۴. ربات مدیر را اجرا کنید:
```bash
python3 antispambot.py
```
مدیر هنگام استارت اسکیمای دیتابیس را می‌سازد، ربات‌های زنده‌ی قبلی را **adopt** می‌کند
(از اجرای دوباره و خطای ۴۰۹ جلوگیری می‌شود) و ربات‌های متوقف را دوباره اجرا می‌کند.

## استفاده
1. در تلگرام به ربات مدیر `/start` بدهید و روی «ساخت ربات انتی اسپم» بزنید.
2. توکن ربات جدید را از @BotFather بگیرید و ارسال کنید (پیام حاوی توکن به‌صورت خودکار حذف
   می‌شود).
3. ربات ساخته‌شده را به گروه اضافه و ادمین کنید (با دسترسی حذف/محدودسازی کاربران).
4. اولین گروه به‌صورت خودکار به‌عنوان گروه مجاز ثبت می‌شود. اعضای جدید تا حل CAPTCHA
   محدود می‌مانند.

### دستورات ربات مدیر
- `/start` — شروع و ساخت ربات
- `/mybots` — مشاهده‌ی وضعیت ربات (شامل گروه تنظیم‌شده و وضعیت پروسه)
- `/help` — راهنما
- `/cancel` — لغو عملیات

### متغیرهای محیطی
| متغیر | توضیح | پیش‌فرض |
|------|-------|---------|
| `MAIN_BOT_TOKEN` | توکن ربات مدیر (الزامی) | — |
| `DATABASE_URL` | DSN پستگرس | `postgresql://antispam:antispam@localhost:5432/antispam` |
| `REDIS_URL` | آدرس Redis | `redis://localhost:6379/0` |
| `BOTS_LOG_DIR` | مسیر لاگ ربات‌های فرزند | `logs` |
| `PG_POOL_MAX` | حداکثر اتصال‌های pool | `10` |
| `PENDING_TTL_SECONDS` | انقضای چالش CAPTCHA | `3600` |
| `LOG_LEVEL` | سطح لاگ | `INFO` |

## سیاست بن
- بعد از **۳** پاسخ اشتباه: بن موقت ۱ ساعته.
- بعد از **۵** پاسخ اشتباه: بن دائم.
- (آستانه‌ها در `config.py` متمرکز‌اند تا متن پیام‌ها و منطق هرگز از هم جدا نشوند.)

## نکات پیاده‌سازی (رفع اشکالات نسخه‌ی قبلی)
- خروجی هر ربات فرزند به فایل لاگ اختصاصی هدایت می‌شود، نه به `PIPE` خوانده‌نشده (که باعث
  هنگ‌کردن بی‌صدای پروسه می‌شد).
- پیش از هر `kill` یا بررسی «زنده بودن»، هویت پروسه از روی `/proc/<pid>/cmdline` تأیید
  می‌شود تا PID بازاستفاده‌شده به‌اشتباه کشته/زنده‌پنداشته نشود.
- تمام دسترسی‌های SQL از طریق connection pool امن انجام می‌شود (بدون کرسر مشترک سراسری).
- توکن‌ها هرگز داخل فایل `.py` نوشته نمی‌شوند و پیام حاوی توکن حذف می‌شود.
